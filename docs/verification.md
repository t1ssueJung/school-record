# GitHub Pages 버전 검증

현재 사용자의 요청에 따라 Apps Script/Google 계정/Drive/Sheets 의존성을 제거했다. 배포 대상은 GitHub Pages 정적 자산이며, 모든 사용자 자료 처리는 브라우저에서 수행한다. 서버 교사 인증·기관 허용 목록·여러 교사 공유 저장소는 이 아키텍처에 포함하지 않는다.

## 검증한 항목

- 단위·통합 테스트 **23개 통과**: 611개 공식 기준, 실제 XLSX 좌표/빈 칸/병합 앵커 파싱, 수식·외부 연결·매크로·비정상 좌표 거부, 명렬표 중복·불변 ID, 1/4/6학년 실제 가명 샘플 생성, 평가 오류, 과목별 보존, 빈 단계 비상속, 승인·CSV·출처 재검증, 저장 실패 복구·저장 후 재열기를 막는 건수 초과 차단, 암호화 백업 형식, 비밀번호 오입력·변조·PBKDF2 설정 변경 거부, 복원 분리, 여러 창 충돌, 비밀번호 변경과 삭제.
- 프로덕션 빌드 성공: HTML/CSS/JavaScript와 가명 샘플만 `dist/`에 들어간다. Apps Script 소스·자격증명·API 키·학생 자료는 배포하지 않는다.
- Playwright/Chromium 자동 테스트 통과: 실제 빌드 자산을 `https://pages.test/school-record/` 출처의 하위 경로에 제공하고, 실제 브라우저의 Web Crypto·IndexedDB·XLSX 파서를 사용했다. 사업 로직·암호화·저장소는 모의 함수로 대체하지 않았다.
- 브라우저 흐름: 저장소 생성 → 오류/정상 명렬표 → 오류/정상 평가 → 초안 생성·승인 → BOM CSV → 과목별 인쇄형 업로드 → 타 과목 승인 보존 → 모바일 390px 가로 넘침 검사 → 암호화 백업 → 새로고침 후 잠김 → 잘못된 비밀번호 거부 → 비밀번호로 재열기 → 백업을 새 저장소로 복원.
- 저장된 IndexedDB 값과 백업 JSON에 가명 학생 이름이나 비밀번호가 평문으로 들어 있지 않은지 검사했다. 브라우저 테스트의 네트워크 요청은 테스트 출처의 정적 자산 GET뿐이며 자료 업로드와 제3자 API 호출은 없었다.

## 확인 범위와 한계

테스트 출처는 프로덕션 빌드 파일을 제공하는 자동화 테스트용 호스트이며 실제 GitHub Pages 배포는 아니다. 관리형 미리보기 relay 연결은 환경에서 실패하여 해당 미리보기는 확인하지 못했다. 실제 GitHub Actions 실행과 Pages 게시 URL은 사용자가 저장소에 올린 뒤 확인해야 한다.

기존 GAS 보안 모델을 그대로 유지했다고 주장하지 않는다. 페이지 접근 자체를 교사 계정으로 제한하지 않고, 해당 기기에 저장한 학생 자료를 비밀번호로 암호화한다. 공개 소스를 열람하는 사람에게는 다른 교사의 브라우저 자료가 전달되지 않는다. 같은 기기의 사용자가 비밀번호를 알고 있거나 이미 열린 화면·브라우저를 사용할 수 있는 경우의 접근까지 차단하지 않는다. 브라우저 데이터 삭제·저장 공간 정리는 자료 손실 원인이므로 암호화 백업이 필요하다.

학교의 실제 보존·접근 통제·기기 정책 적합성, 최신 정오표, 교육청별 학업성적관리 규정, 교사가 입력한 평가 결과의 사실관계·성취수준과의 일치 여부는 담당 교사가 확인한다. 앱의 교사 승인 표시는 나이스의 공식 결재가 아니다.

## 직접 배포 화면 복구

원본 `index.html`이 저장소 루트에 그대로 게시되면 `/src/main.js`의 절대 경로와 번들되지 않은 npm import 때문에 CSS/JavaScript가 실행되지 않았다. 개발 진입점을 `app.html`로 분리하고, 저장소 루트 `index.html`·`assets/`·`samples/`에 빌드 완료본을 제공하도록 수정했다. GitHub Pages의 저장소 하위 경로에서 이 루트 파일들이 모두 연결되는 회귀 검사를 추가했다. 저장 데이터 형식과 암호화 저장소는 변경하지 않았다.
